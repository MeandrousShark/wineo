# 0002: Everyday management

Status: draft

## Goal

Round out day-to-day use: remove environments, run winetricks in them, complete verbs and flags in the shell, and keep a long session's log from growing without limit.

## Decisions

Settled by the maintainer:

- The plan covers four priority 1 rows from `docs/features.md`: the `rm` verb, `wineo winetricks`, shell completion for verbs and flags, and a log size cap. Per-environment process tracking waits until real apps show whether 0001's program exit tracking is enough.
- `rm` keeps the prefix unless `--delete-prefix` is passed, and refuses while the environment is running.
- `winetricks` refuses to run while the environment is running, since several winetricks verbs wait for every wine process in the prefix to exit.
- `wineo completions <shell>` prints the completion script, and the user saves it where their shell looks.
- When a detached run's log passes the size cap, wineo empties it and notes that earlier output was dropped, so the log keeps the newest output.

## Proposed details

Everything in this section is a proposal for review.

### `wineo rm <name>... [--delete-prefix]`

- Removes each environment's config file and its runtime state dir (`state.toml`, the logs, `create.log`, the lock).
- Every name is checked before anything is removed, so `wineo rm a b` removes nothing if `b` is running or doesn't exist.
- A running environment is refused with `<name> is running, stop it first`. The run lock is held while removing, so `start` can't begin partway through.
- Output: `Removed environment photoshop, its prefix is still at ~/Apps/Photoshop`, or with `--delete-prefix`, `Removed environment notepad and its prefix`.
- `--delete-prefix`:
  - Deletes the prefix dir without following symlinks, since a prefix links `z:` to `/` and its user folders to the home directory.
  - Refuses a dir that isn't a wine prefix (no `system.reg`), so a config pointing at the wrong dir can't delete it. A prefix dir that's already gone is noted and skipped.
  - Applies to adopted prefixes outside the prefix root too, since the flag is explicit.
  - The prefix is deleted first and the config last, so a failure partway leaves the environment listed and `rm` can be retried.
- Broken configs can still be removed. Only `--delete-prefix` needs to read the config, for the prefix path.

### `wineo winetricks [-e KEY=VAL]... <name> [winetricks args...]`

- Runs `winetricks` from PATH attached, like `exec`, with:
  - `WINEPREFIX` set to the prefix, and `WINE` and `WINESERVER` set to the environment's runner, so it uses the same wine as `start`.
  - The merged `[env]` tables and `-e` values, with the menu builder override from 0001.
- Everything after the name goes to winetricks, including its flags like `-q` or `--force`, so no `--` is needed. `-h` still shows wineo's help, so `wineo winetricks notepad -- -h` passes it on.
- No arguments opens the winetricks GUI.
- Refuses while running with `<name> is running, stop it before running winetricks`, and refuses a missing prefix, like `exec`.
- `winetricks` missing from PATH is an error: `` `winetricks` was not found on PATH ``.
- Doesn't take the run lock, like `exec`.
- The exit code passes through.

### `wineo completions <shell>`

- Prints the script for `bash`, `elvish`, `fish`, `powershell`, or `zsh` to stdout, generated by `clap_complete` from the same clap definitions, so it never goes stale.
- Covers verbs and flags. Environment and target names stay a separate, later feature.
- Hidden commands like `__supervise` are left out.
- New dependency in the CLI crate: `clap_complete`.

### Log size cap

Global config:

```toml
# ~/.config/wineo/config.toml
log_limit_mb = 50        # 0 turns the cap off
```

- Defaults to 50. `wineo set --global log_limit_mb=100` works like `stop_timeout`.
- The limit is read when a run starts, so a change applies from the next start.
- The supervisor checks the log's size every second. Once it's over the limit, the supervisor empties the file and writes `wineo: the log passed 50 MB, so earlier output was dropped`. Wine keeps writing straight to the file in append mode, so nothing about the app changes.
- `output.log.1` still keeps the previous run's log, so one environment uses at most about twice the limit.
- `wineo logs -f` notices when the log shrinks and continues from the start of the file.
- Attached runs aren't logged, so the cap doesn't apply to them.

### Testing

- `rm`: CLI tests without wine for removing config and state, keeping the prefix, `--delete-prefix` on a fake prefix with a symlink out of it (whatever it points at must survive), refusing a non-prefix dir, refusing while running, and several names at once.
- `winetricks`: a fake `winetricks` script on PATH that prints its arguments and the `WINEPREFIX`, `WINE`, `WINESERVER`, and `WINEDLLOVERRIDES` it got, then exits with a chosen code. Covers refusing while running and a missing `winetricks`.
- `completions`: every shell produces a script, and the fish one mentions `start` but not `__supervise`.
- Log cap: a fake program that writes a few MB quickly with `log_limit_mb = 1`, checking the marker line, the size staying near the limit, and `logs -f` following through the drop.
- Ignored real wine tests: `winetricks list-installed` on a fresh prefix, and a `WINEDEBUG=+all` notepad run with `log_limit_mb = 1`.

## Phases

1. `rm`, `completions`, and `winetricks`.
2. Log size cap.

Each phase ends with tests, fmt, and clippy passing, then a commit and push.

## Done when

With wine and winetricks installed:

```
wineo completions fish > ~/.config/fish/completions/wineo.fish
wineo st<Tab>                              # offers start, status, stop
wineo new -n notepad
wineo set notepad targets.notepad.exe=notepad
wineo start notepad
wineo winetricks notepad list-installed    # refuses, notepad is running
wineo stop notepad
wineo winetricks notepad list-installed    # runs against the notepad prefix
wineo set --global log_limit_mb=1
wineo start notepad -e WINEDEBUG=+all      # output.log stays near 1 MB
wineo stop notepad
wineo rm notepad                           # prefix is kept
wineo new -n notepad --dir ~/.local/share/wineo/prefixes/notepad
wineo rm notepad --delete-prefix           # prefix is gone
```

## Open questions

Proposed answers in parentheses.

1. Should `winetricks` hold the run lock, so `start` can't launch the app in the middle of an install? (no, like `exec`, revisit if it causes trouble)
2. Should `log_limit_mb` also be settable per environment? (not now, the global setting is enough until one app needs different limits)
3. `features.md` loses the four rows this plan covers once it's approved, and the dynamic completion row points at 0002. (yes)
